# Track Specification: Sniffle BLE Advertisement Scans Ingestion

## Overview
This feature adds native support for ingesting Bluetooth Low Energy (BLE) advertisement and scan capture datasets generated by the Sniffle BLE sniffer (exported via Wireshark/tshark JSON format, as exemplified by `sniffle.json`). It introduces a dedicated `BleAdvertisementMessage` and unified `TelemetryEnvelope` in `proto/telemetry.proto`, a low-memory streaming JSON parser (`SniffleJsonReader`), filtering capabilities (CRC validation, RSSI thresholding), timing options (real-time delta playback or fixed intervals), and seamless integration into the existing `TelemetryPipeline`, `SqliteSpooler`, and `PubSubPublisher`.

## Functional Requirements

### 1. Protobuf Schema Updates (`proto/telemetry.proto`)
- Define `BleAdvertisementMessage` with the following fields:
  - `string device_id`: ID of the sniffer node (e.g., `sniffle-01`).
  - `string timestamp_iso`: ISO 8601 UTC timestamp.
  - `int64 timestamp_epoch_ms`: Milliseconds since epoch.
  - `int32 channel`: BLE RF channel index (e.g. 0-39, advertising channels 37, 38, 39).
  - `int32 signal_dbm`: RSSI signal strength in dBm.
  - `string access_address`: BLE access address (hex).
  - `string pdu_type`: BLE advertising PDU type (e.g. `ADV_IND`, `SCAN_REQ`, `SCAN_RSP`, `ADV_NONCONN_IND`, `ADV_SCAN_IND`).
  - `string advertiser_mac`: Advertiser MAC address (`aa:bb:cc:dd:ee:ff`).
  - `string scanner_mac`: Scanner MAC address (for SCAN_REQ).
  - `string device_name`: Parsed local name from EIR/AD entries if present.
  - `string company_id`: Parsed manufacturer company ID (e.g. Apple `0x004c`, Microsoft `0x0006`).
  - `bytes adv_data_raw`: Raw advertisement payload / service data bytes.
  - `bool crc_valid`: Boolean flag indicating packet CRC checksum validity.
  - `map<string, string> metadata`: Extensible metadata.
- Define `TelemetryEnvelope` wrapper:
  ```protobuf
  message TelemetryEnvelope {
    oneof payload {
      RfTelemetryMessage spectral_sweep = 1;
      BleAdvertisementMessage ble_advertisement = 2;
    }
  }
  ```
- Update Protobuf compilation script (`scripts/compile_proto.py`) to generate updated classes.

### 2. Streaming Sniffle JSON Reader (`src/agent/sniffle_reader.py`)
- Implement `SniffleJsonReader` capable of processing large multi-megabyte/gigabyte packet dumps without high memory consumption.
- Parse `_source.layers`:
  - `frame`: `frame.time_utc`, `frame.time_epoch`, `frame.time_delta`, `frame.protocols`.
  - `btle_rf`: `btle_rf.channel`, `btle_rf.signal_dbm`, `btle_rf.flags_tree.btle_rf.flags.crc_valid`.
  - `btle`: `btle.access_address`, `btle.advertising_header_tree.btle.advertising_header.pdu_type`, `btle.advertising_address`, `btle.scanning_address`, `btle.scan_response_data`.
  - `btcommon.eir_ad.advertising_data`: Extract device name, company ID, service UUIDs.
- Filtering options:
  - CRC error filtering: Skip packets where `crc_valid == 0` (enabled by default).
  - Minimum RSSI filter: `--min-rssi` threshold (e.g. drop packets weaker than specified dBm).
- Playback & Timing:
  - Realtime delta playback option (`realtime=True` using `frame.time_delta`).
  - Fixed interval delay option (`interval_sec`).
  - Continuous loop option (`loop=True`).

### 3. Pipeline & Publisher Integration
- Adapt `TelemetryPipeline` to handle both `RfTelemetryMessage` and `BleAdvertisementMessage` (or `TelemetryEnvelope`).
- Adapt `PubSubPublisher` to publish either message type with appropriate message attributes (`telemetry_type="ble_advertisement"` vs `telemetry_type="spectral_sweep"`).
- Support dedicated `--ble-topic-id` if specified, defaulting to primary `--topic-id`.

### 4. CLI & Observability
- Add CLI arguments in `src/agent/cli.py`:
  - `--sniffle-json <path>`: Path to Sniffle JSON file.
  - `--min-rssi <int>`: Minimum RSSI threshold in dBm.
  - `--realtime`: Enable packet time-delta playback simulation.
  - `--ble-topic-id <str>`: Separate GCP Pub/Sub topic for BLE scans.
- Add Prometheus counters:
  - `ble_packets_processed_total`: Count of processed BLE packets.
  - `ble_packets_crc_errors_total`: Count of dropped corrupt packets.

## Non-Functional Requirements
- **Low Memory Overhead:** Streaming reader maintains constant O(1) memory usage regardless of capture file size (suitable for 73MB+ or multi-GB captures).
- **Test Coverage:** >80% test coverage across new and updated modules.
- **Backwards Compatibility:** Existing spectral sweep CSV ingestion and pipeline functions continue to operate without regression.

## Acceptance Criteria
- [ ] Protobuf schema compiles cleanly with `BleAdvertisementMessage` and `TelemetryEnvelope`.
- [ ] `SniffleJsonReader` streams packets from `sniffle.json` and small fixture without loading entire file into memory.
- [ ] Filter flags properly drop CRC-invalid packets and sub-threshold RSSI packets.
- [ ] Pipeline processes and serializes BLE messages into SQLite spooler and Pub/Sub publisher.
- [ ] CLI runs with `--sniffle-json` and `--dry-run` against `sniffle.json`.
- [ ] All unit and integration tests pass with >80% coverage.

## Out of Scope
- Direct live USB / UART serial Sniffle hardware capture daemon (reading from serial / ttyUSB) — deferred to future hardware integration track.
- Bluetooth Classic / BR/EDR packet decoding.
